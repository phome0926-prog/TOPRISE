# TOPRISE 営業資料 PWA — 公開と運用の手引き

このフォルダ一式を Web 上のどこかに置けば、iPad の「ホーム画面に追加」でアプリ化できます。
追加後はオフラインでも表示できます。

> **現在の公開場所について**
> 2026年9月時点、このアプリは制作者（溝口）個人の GitHub アカウント上で公開しています。
> この公開ページは当面残しますが、**維持・更新は保証されません**。
> 御社の管理下で運用したい場合は、下記「7. 御社のアカウントで公開し直す（引き継ぎ手順）」に沿って移してください。
> 所要時間は 30 分程度、費用はかかりません。

## 1. このフォルダの中身

```
toprise-app/
├── index.html                  ← 目次画面（PWAのトップ）
├── manifest.json               ← アプリ宣言（名前・アイコン・テーマ色）
├── service-worker.js           ← オフラインキャッシュ（CACHE_VERSION はここ）
├── icons/
│   ├── icon-192.png
│   ├── icon-512.png
│   └── apple-touch-icon.png    ← iOS ホーム画面アイコン
├── toprise_advisor.html        ← 手法選定アドバイザー（商談用・タップで推奨手法を提案）
├── toprise_company.html        ← 会社紹介
├── toprise_field_cards.html    ← 現場提案カード（iPad現場用）
├── toprise_sheet_p40.html      ← Leica P40 機材シート
├── toprise_sheet_navvis.html   ← NavVis VLX 機材シート
├── toprise_sheet_uav.html      ← DJI Matrice 350 RTK 機材シート
├── toprise_sheet_proscan.html  ← ProScan 機材シート（※導線からは外しています。将来復活用に保管）
├── toprise_guide.html          ← 営業担当向け「使い方」ページ（目次からリンク。PDF版も同内容）
└── README.md                   ← このファイル
```

## 1-1. 画面の構成

目次（index.html）から次の画面に飛べます：

- **手法選定アドバイザー** … 商談の主役。お客様の現場条件をタップで選ぶと「この手法がベスト」＋理由＋作業コスト（どの工程に手間がかかるか）を提示。手法から／成果物からの逆引きも可。
- **会社紹介** … 元請ゼネコン向け。3D計測（3手法）・BIM/CIM・ドローン・災害・沿革・会社概要。
- **現場提案カード** … 要望をタップすると技術ポイント・手法・機材・精度・成果物・納期が1画面で出る。
- **機材シート（3手法）** … Leica P40／NavVis VLX／DJI Matrice 350 RTK。

## 2. PWA が動く条件

- **HTTPS で配信されていること**（http:// では Service Worker が動きません。`localhost` だけ例外）
- ファイルが**そのままの構造**で同じフォルダに置かれていること
- `index.html` を入口に開くこと

これを満たせばホスティング先は何でもよいです。代表的な無料の選択肢：

### 選択肢A：GitHub Pages（おすすめ・無料・HTTPS自動付与）

1. GitHub に新しいリポジトリ（例：`toprise-app`）を作成。Public で OK。
2. このフォルダの中身**すべて**をリポジトリのルートにアップロード（ドラッグ＆ドロップでもよい）。
3. リポジトリの **Settings → Pages** を開く。
4. *Source* を「Deploy from a branch」、Branch を `main` / `(root)` に設定して Save。
5. 1〜2分待つと URL が表示される（例：`https://<ユーザー名>.github.io/toprise-app/`）。
6. iPad の Safari でその URL を開く → 共有ボタン `[↑]` → **「ホーム画面に追加」**。
7. ホーム画面にTOPRISEのロゴのアイコンができる。タップでフルスクリーン起動・オフライン対応。

### 選択肢B：Netlify Drop（さらに手軽・要アカウント1つ）

1. [https://app.netlify.com/drop](https://app.netlify.com/drop) にアクセス。
2. このフォルダを丸ごとドラッグ＆ドロップ。
3. 表示された URL（例：`https://xxx.netlify.app/`）を iPad で開いて「ホーム画面に追加」。

### 選択肢C：社内サーバ／既存の自社ドメイン配下

すでに会社の Web サーバがあるなら、`/toprise-app/` のようなパスに上記ファイルを置くだけ。
HTTPS であることだけ確認してください。

## 3. iPad へのインストール手順

1. Safari でアプリの URL を開く（`https://...` で始まる URL）
2. 画面下の **共有ボタン**（四角＋上矢印のアイコン）をタップ
3. メニューを下にスクロールして **「ホーム画面に追加」** をタップ
4. 名前を確認（デフォルトで「TOPRISE」）→ 「追加」
5. ホーム画面にTOPRISEのロゴのアイコンが現れる。タップで全画面起動。

**ポイント**：初回はオンラインで開いてください。2回目以降は機内モードでも開けます。

## 4. 資料を更新したいとき

中身（例：`toprise_sheet_p40.html`）を差し替えただけでは、ホーム画面アプリは
**キャッシュ済みの古いバージョンを表示し続けます**。

新しい内容を反映するには、`service-worker.js` の冒頭にある以下の行を変更してください：

```javascript
const CACHE_VERSION = "toprise-v19";  //  ← 更新のたびに v20, v21 … と数字を上げる
```

数字を1つ上げてからアップロードすると、次にオンラインで開いたとき
古いキャッシュが破棄され、最新のファイルが再キャッシュされます。
（現在のバージョンは **v19** です。次に更新するときは v20 にしてください）

> 簡単ルール：**資料を1回でも触ったら、必ず CACHE_VERSION の数字を1つ上げる**

## 5. うまく動かないとき

| 症状 | 原因 / 対処 |
|---|---|
| 「ホーム画面に追加」が出ない | Safari 以外（Chrome等）で開いていませんか？ iOS では Safari のみ対応 |
| 古い内容が表示される | `CACHE_VERSION` を上げ忘れ。上げて再アップ→Safariで一度開き直す |
| アイコンが灰色になる | `apple-touch-icon.png` が正しい場所にあるか確認 |
| オフラインで開けない | 初回はオンラインで一度開く必要がある。フォント等の取得が完了するまで2〜3秒待つ |
| URL が変わった | ホーム画面アイコンを削除して、新しい URL で「追加」し直す |

## 6. 制限事項（正直なところ）

- iOS では Service Worker のキャッシュは **数週間アクセスが無いと OS に削除される**ことがあります。
  営業現場で定期的に開いていれば問題になりませんが、長期間放置するとオンライン接続が必要になります。
- App Store には載りません（その代わり審査・年99ドルの開発者登録は不要です）。
- プッシュ通知は iOS 16.4 以降で可能ですが、このアプリでは使っていません。


## 7. 御社のアカウントで公開し直す（引き継ぎ手順）

制作者のアカウントから御社のアカウントへ「移す」のではなく、**御社のアカウントで新しく公開し直す**方法です。
専門知識は不要で、この手順どおりに進めれば 30 分ほどで完了します。誰にも問い合わせる必要はありません。

### 7-1. 用意するもの

- パソコン（Windows / Mac どちらでも）とブラウザ（Chrome か Safari か Edge）
- 御社のメールアドレス（個人のものではなく、会社で管理できるもの。担当者が変わっても引き継げるアドレスが望ましい）
- スマートフォン（二段階認証の設定に使います。担当者のもので可）
- このフォルダ一式（`toprise-app.zip` を展開したもの）

### 7-2. GitHub のアカウントを作る（無料）

1. ブラウザで **https://github.com** を開き、右上の **Sign up** をクリック
2. メールアドレス → パスワード → **ユーザー名** の順に入力
   - ユーザー名は **そのまま公開URLの一部になります**。社名が入ったものが自然です（例：`toprise-niigata`、`toprise-sales`）
   - 使えるのは半角英数字とハイフンのみ。すでに他人が使っている名前は登録できないので、その場合は別の名前にしてください
3. 登録したメールアドレスに確認メールが届くので、メール内のリンクを開いて認証を完了
4. ログイン後、二段階認証（Two-factor authentication）の設定を求められることがあります。求められたら **担当者のスマートフォン** に認証アプリ（Google Authenticator など）を入れて設定してください。表示される **リカバリーコードは必ず控えて社内で保管**してください（担当者交代時に必要になります）

### 7-3. リポジトリ（保管場所）を作る

1. ログインした状態で、画面右上の **「＋」** → **New repository**
2. **Repository name** に `TOPRISE` と入力（別の名前でも構いませんが、これもURLの一部になります）
3. **Public** を選択（Public でないと無料では公開できません。中身は営業資料なので Public で問題ありませんが、気になる場合は資料内容をご確認ください）
4. 下のチェック項目（Add a README など）は **すべて触らず**、緑の **Create repository** を押す

### 7-4. ファイルをアップロードする

1. 作成直後の画面に **「uploading an existing file」** という青いリンクがあるのでクリック
   （見当たらない場合は、リポジトリ画面上部の **Add file → Upload files**）
2. `toprise-app.zip` を展開し、**中身をすべて選んで**、点線で囲まれた枠にドラッグ＆ドロップ
   - **重要**：`toprise-app` フォルダごとではなく、**フォルダの中身**を入れます
   - `icons` フォルダは **フォルダのまま** 入れます（中の画像をバラさない）
   - 入れるもの：index.html／manifest.json／service-worker.js／icons フォルダ／toprise_ で始まる HTML ファイルすべて／README.md
3. ファイル名が一覧に並んだのを確認して、画面下の緑の **Commit changes** を押す
4. アップロード後、リポジトリのトップに `index.html` や `icons` が **直接** 見えていれば正解です。
   `toprise-app` というフォルダが 1 つだけ見えていたら、フォルダごと入れてしまっています。その場合はそのフォルダを開いて中身をもう一度 7-4 の手順で上げ直してください

### 7-5. 公開設定（GitHub Pages）を有効にする

1. リポジトリ画面上部のタブから **Settings**（歯車マーク）をクリック
2. 左側のメニューを下にスクロールして **Pages** をクリック
3. **Build and deployment** の **Source** が **Deploy from a branch** になっているのを確認
4. **Branch** のプルダウンで、左を **main**、右を **/ (root)** にして **Save**
5. 1〜2 分待ってから、同じ画面を再読み込み（リロード）すると、上部に
   **「Your site is live at https://（ユーザー名）.github.io/TOPRISE/」** と表示されます。これが **御社の新しい公開URL** です
   - 最初の数分は「404」と出ることがありますが、少し待って再読み込みすれば表示されます

### 7-6. iPad 側の切り替え

公開URLが変わるので、営業担当の iPad で次を行ってください。

1. ホーム画面の古い TOPRISE アイコンを長押し → 削除
2. Safari で **新しいURL** を開く → 共有ボタン → **ホーム画面に追加**
3. 一度ネットにつながった状態で開いておく（以後はオフラインでも動きます）

アプリ内の「使い方」ページに表示されるURLは、**公開先に合わせて自動で切り替わります**（書き換え不要）。
PDF 版の使い方には旧URLが印刷されていますので、配布し直す場合はアプリ内の「使い方」ページを正としてください。

### 7-7. 以後の更新のしかた

内容を直したいときは「4. 資料を更新したいとき」のとおりです。要点は 2 つだけ：

- 直したファイルを 7-4 と同じ手順で上げ直す（同じ名前なら自動で上書き）
- `service-worker.js` の `CACHE_VERSION` の数字を **1 つ上げる**（これを忘れると iPad に古い内容が残ります）

ファイルの中身（文言や画像）を編集するには、GitHub 上でファイルを開いて右上の鉛筆マーク（Edit）から直接書き換え、下の Commit changes で保存できます。
HTML の編集に不安がある場合は、社内で Web に詳しい方か、外部の制作会社に「GitHub Pages 上の静的 HTML の修正」として依頼すれば、一般的な作業として対応してもらえます。

### 7-8. 旧公開ページについて

制作者側の公開ページ（`phome0926-prog.github.io/TOPRISE/`）は、御社側で新URLの運用が始まったあとは使いません。
いつ停止しても御社の運用には影響しないよう、この手順で独立させておく、というのがこの節の目的です。

---

何か困ったら、HTMLファイルを直接 Safari で開けば普通の Web ページとして見られます。
PWA は「便利な皮」であって、中身は普通の HTML なので、最悪 PWA が動かなくても資料は失われません。
